# Развёртывание и импорт данных

## Что нужно

Docker с плагином Compose. На Windows подходит Docker внутри WSL или Docker Desktop. Требования к
ресурсам и замеры, на которых они основаны, приведены в конце документа.

## Первый запуск

```bash
sh tools/init_env.sh      # создаёт .env со случайными секретами
sh tools/make_cert.sh     # самоподписанный сертификат для проверки
docker compose --profile demo up -d --build
docker compose ps
```

Профиль `demo` включает Mailpit, почтовый сервер для проверки: письма сервиса видны на
`http://127.0.0.1:8025`. Сервис открывается на `https://localhost:8443`. Браузер предупредит о
самоподписанном сертификате.

Порядок запуска задан в `compose.yaml`: база и Redis, затем одноразовый контейнер `migrate`
применяет миграции, затем сервис и прокси. Сервис не стартует, пока миграции не выполнены.

## Работа в открытой сети

| Что сделать | Как |
|---|---|
| Указать адрес сервиса | `KB_PUBLIC_URL` в `.env`: на него ведут ссылки из писем |
| Положить настоящий сертификат | `deploy/certs/server.crt` и `server.key` |
| Подключить настоящую почту | `KB_SMTP_HOST`, `KB_SMTP_PORT`, `KB_SMTP_USER`, `KB_SMTP_PASSWORD`, `KB_SMTP_STARTTLS=true`, запуск без профиля `demo` |
| Закрыть страницы документации | `KB_DOCS_ENABLED=false` |
| Занять стандартные порты | `KB_HTTP_PORT=80`, `KB_HTTPS_PORT=443` |

Ключ `KB_JWT_SECRET` менять нельзя без необходимости: все выданные токены станут недействительными,
пользователям придётся войти заново.

## Обновление

```bash
git pull
docker compose --profile demo up -d --build
```

Контейнер `migrate` применит новые миграции. Поисковые индексы хранятся в памяти и строятся заново
при запуске, кэш при этом сбрасывается.

## Резервное копирование

```bash
sh tools/backup.sh
```

Скрипт создаёт копию в `backups/`, восстанавливает её во временную базу и сравнивает число строк с
рабочей базой. Восстановление рабочей базы из копии:

```bash
docker compose stop app
docker compose exec -T db pg_restore -U kb -d kb --clean --if-exists < backups/файл.dump
docker compose start app
```

## Импорт данных

Импорт принимает файлы Markdown в кодировке UTF-8, размер каждого не больше 5 МБ. Шапка YAML
необязательна.

```markdown
---
title: Индексы в PostgreSQL
tags: [postgresql, производительность]
category: Базы данных
author: Автор
created: 2026-09-14
---
```

**Через веб-интерфейс.** Раздел «Документы»: перетащите файлы в выделенную область или выберите их на
диске.

**Через API.** Сначала получите токен:

```bash
curl -k -X POST https://127.0.0.1:8443/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "anna@example.org", "password": "ваш пароль"}'
```

Затем загрузите файлы:

```bash
curl -k -H "Authorization: Bearer $TOKEN" \
  -F "files=@samples/postgresql-indexes.md" \
  -F "files=@samples/redis-cache.md" \
  https://127.0.0.1:8443/api/v1/documents/import
```

Ответ показывает, что произошло с каждым файлом: `created`, `updated`, `unchanged` и `failed` с
причиной. Плохой файл не мешает загрузке остальных. Повторный импорт файла с тем же именем создаёт
новую версию, только если текст изменился. Поэтому импорт каталога можно повторять без дублей.

## Проверка после запуска

```bash
docker compose ps
curl -k https://127.0.0.1:8443/api/v1/health
python tools/api_smoke.py https://127.0.0.1:8443 http://127.0.0.1:8025
python tools/security_smoke.py https://127.0.0.1:8443 http://127.0.0.1:8025
```

## Ограничения

- Рабочий процесс сервиса один: поисковые индексы хранятся в памяти процесса. Для нескольких
  процессов индекс нужно вынести во внешнее хранилище.
- Шифрования данных на диске сервис не делает. Если оно нужно, том базы размещается на зашифрованном
  диске.
- Токен обновления действует до конца срока или до выхода: обновление не отзывает прежний токен.
- Если Redis недоступен, ограничение попыток входа не действует, в журнале появляется предупреждение.
